# Contributing

1. Keep changes focused and explain the intended behavior.
2. Add or update tests for changed behavior.
3. Do not commit local state, secrets, customer data, raw captures, or generated reports.
4. Preserve provenance when adding external research: source URL, publication date, and validation status.
5. Distinguish hypotheses from reproduced findings.
6. Prefer incremental Rust components when profiling demonstrates a need; avoid broad rewrites without benchmarks.

Run the relevant test subset before opening a pull request and include the command and result in the description.
